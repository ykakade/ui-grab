A Vite dev plugin. Click elements in your running app, type what should change, batch them up, hit Send — and Claude Code picks up the batch with the file and line each one probably lives on already attached. No extension, no daemon, no MCP server.

The page's source, so you can check the line numbers

The candidates above come from the plugin's own ranking — exact text first, then id and data-testid, then aria-label and the whole class attribute, then single class names — with a line that actually opens the element's tag beating one that merely contains the same string. Here it runs in your browser over this page's two files; in your project it runs in Node over the whole tree, and adds the enclosing declaration for the best hits.

then what

Over in Claude Code

The batch lands in .ui-grab/queue.json. One command drains it — or none at all, if you turn on a zero-typing mode. 

$ npm run dev
  ui-grab  queued 2 changes (2 pending) → .ui-grab/queue.json

> /grab
  ⏵ Read .ui-grab/queue.json
  ⏵ Update index.html          button#place-order — 1.25×, proportions kept
  ⏵ Update src/style.css       .checkout-title line-height 1.35 → 1.15
  ✓ Applied 2 changes, queue cleared
modewhat happens when you hit Send
offNothing — you run /grab yourself.
waitThe Stop hook holds each turn open a few seconds longer, so a click made just after Claude finishes still lands in the same turn.
wakeAn idle session gets poked the moment a batch arrives — typed straight into its tmux pane.
bothWait first; wake if that window passes. The default.
pointers

It sends a pointer, not a snapshot

You might click at 2pm and drain at 4pm, after the file has been edited twice. A snapshot would be a lie by then; a file, a line, a class list and some text still finds the right place.

ranking

Checked, not trusted

With react-grab installed it reads the component and line straight off the fiber — then verifies that line against the source.

A reading that doesn't corroborate drops below the grep hits and says line unverified. A confidently wrong line is worse than an honest guess.

local only

The queue is instructions

Whatever lands in it is what an agent goes on to do, so the endpoint takes writes only from a page served locally — a cross-site POST is refused outright.
